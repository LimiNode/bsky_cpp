# `v0.1.0-alpha.1` release preparation

Status: release-candidate preparation record. Publication is a separate step
performed only after approval on the exact verified `main` commit.

The engineering-preview gate is intentionally held until the SDK demonstrates
one real read-only Bluesky operation. The first public alpha therefore also
requires the concrete native `kurlyk` adapter, minimal XRPC query/response
mapping, and an end-to-end `app.bsky.actor.getProfile` example. The manifest
and packaging checks remain valid preparation work; this decision does not
authorize creating a tag or GitHub Release.

## Release identity

- Package: `bsky_cpp`
- Preview version: `0.1.0-alpha.1`
- CMake and linked-library version: `0.1.0`
- Planned tag: `v0.1.0-alpha.1`
- CMake package compatibility: `SameMinorVersion` for the pre-1.0 `0.x` line
- Components: foundation and opt-in `runtime`
- Manifest: [`release-manifest.json`](../../release-manifest.json)

The pre-release suffix belongs to the release and tag identity. CMake keeps the
numeric library version at `0.1.0`; the release notes and manifest carry the
preview label without introducing a second version parser.

## Supported build envelope

- C++17
- CMake 3.20 or newer
- Windows, Linux, and macOS CI configurations
- Foundation without initialized optional submodules
- Runtime with the pinned `external/event-hub-cpp` submodule

## Implemented in this preview

The foundation contains validated AT Protocol identifier values, typed results
and errors, cooperative cancellation, and owned transport-neutral values. The
opt-in runtime contains the reviewed M1c operation subset, the bounded blocking
transport bridge, deadlines, callback quiescence, and the M1d1 native async
transport-neutral seam. See [`IMPLEMENTATION_STATUS.md`](../IMPLEMENTATION_STATUS.md)
for source and test evidence.

## Known limitations

There is no Bluesky network `Client`, XRPC implementation, authentication,
identity resolution, `kurlyk` adapter, retry policy, persistence, stream, or
high-level social API. Native async completion is an adapter boundary, not a
network implementation. The `0.x` API is not stable across minor releases.

GitHub source archives do not contain the contents of git submodules. Runtime
consumers must obtain `external/event-hub-cpp` separately or use an installed
runtime package with its dependency available to CMake.

## Verification checklist

The release gate requires the dependent PRs to be merged and the post-merge
`main` CI to pass before creating a tag or release:

1. Foundation Debug and Release CTest.
2. Runtime Debug and Release CTest.
3. Installed foundation and runtime consumers.
4. Package-version compatibility: `0.1` accepted and `0.2` rejected.
5. Public-header self-containment and Doxygen warnings-as-errors.
6. Markdown link checker and regression test.
7. Linux ASan/UBSan and TSan jobs.
8. Windows/Linux/macOS Debug and Release jobs.
9. `git diff --check` on the release-preparation PR.

The exact merge and workflow SHAs are recorded in the review handoff; this
document does not create or publish a release.
